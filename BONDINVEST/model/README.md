# BONDINVEST/model — математическая модель участия (Python, source of truth)

Сюда вынесена **вся финансовая математика** продукта. Фронтенд больше не хранит
веса в TS-коде: они живут в `config.yaml` и экспортируются в приложение JSON-ом.

## Формула

```
Индекс = base_index(0.1) + Б(стрейк/лояльность) + Б(объём) + Б(активность)
Ожидаемый бонус ₽/год = Индекс × rub_per_index_point × (депозит / 1000₽)
Доходность пользователя = гарантия 4% + надбавка (Индекс × 7.5 п.п.)
Маржа компании = ОФЗ(11%) − надбавка − резерв(1%)
```

Пороги по умолчанию (из ТЗ): стрейк 8 нед → +0.3 / 20 нед → +0.5;
объём 2000₽ → +0.2 / 5000₽ → +0.4; активность 3/мес → +0.2 / 6/мес → +0.3.
Максимум индекса 1.3 ≈ «до 10% годовых» при депозите 1000₽.

## Файлы

| Файл | Назначение |
|---|---|
| `config.yaml` | **Все веса модели**: пороги, бонусы, курс ₽/индекс, экономика. Правьте здесь — код менять не нужно. |
| `model.py` | Загрузка/валидация конфига, расчёт индекса, статусов целей, денег, маржи; экспорт JSON для фронта. |
| `api.py` | HTTP API на stdlib: `GET /api/index`, `GET /api/config`, `POST /api/reload` (горячая смена весов). |
| `tests/test_model.py` | 19 тестов: формула, границы порогов, экономика, антигейминг, стресс-сценарии, смена весов через конфиг. |
| `requirements.txt` | PyYAML (+pytest опционально). |

## Быстрый старт

```bash
pip install -r requirements.txt

python3 model.py                 # демо-расчёт мок-пользователя (индекс 0.6, ~45₽/год)
python3 api.py --port 8000       # сервер модели: http://127.0.0.1:8000/api/index?...
curl "http://127.0.0.1:8000/api/index?loyalty=12&volume=1500&activity=4"
curl -X POST http://127.0.0.1:8000/api/reload   # перечитать config.yaml без рестарта

# регенерация весов для фронтенда (app/src/generated/model-config.json):
python3 -c "from model import export_frontend_config; export_frontend_config()"

# тесты
python3 -m unittest discover -s tests        # или python3 -m pytest tests -q
```

## Как менять веса выплат

1. Откройте `config.yaml`, поменяйте, например, бонус объёма `0.2 → 0.25`
   или добавьте третий порог `{ value: 10, bonus: 0.4 }`.
2. Выполните `POST /api/reload` (или перегенерируйте JSON командой выше).
3. Модель, API и карточки фронта считают по новым весам — потолок индекса
   (`maxIndex`) пересчитывается автоматически из суммы лучших бонусов.

Валидация конфига падает сразу при пустых порогах, неположительных бонусах,
дублях значений или отсутствии обязательных целей — битые веса не «просочатся»
в расчёт выплат.

## Связь с фронтендом

`app/src/generated/model-config.json` — сгенерированныйartifact, фронт может
строить карточки целей из него (см. `backend_plan.yaml`, шаг интеграции API).
Пока приложение работает на моках, но значения в `types.ts`
(`INDEX_TO_RUB = 75`, `MAX_PARTICIPATION_INDEX = 1.3`) совпадают с моделью —
паритет закреплен тестом `test_mock_user_parity_with_frontend`.
